# 失败与降级语义

Type: grilling
Status: resolved

## Question

看板由四个外部依赖拼出来（Jira、GitLab、Jenkins、轮询），任何一个不可用或慢到超时，界面都要给出一个「诚实的不好看」，而不是猜。

需要定的：

- **写失败如何回滚**：拖拽是乐观更新（先移动卡片再发请求）还是悲观（等 200 再移动）？失败后卡片弹回原列时怎么让人知道原因（气泡 / 底部条 / 卡片红边）。
- **部分数据源缺失**：GitLab 未配置 → 全部卡片停在「未提交」是**错的**（应该是「未知」）。需要一个区别于五级阶梯的第六态「无法判定」，否则用户会照着假信号行动。这一条要显式确认。
- **凭据失效**：Jira 401 / GitLab 401 / Jenkins 403 的提示要能指到「改哪个配置文件」，不能只说「请求失败」。
- **超时**：现有 JiraService 超时 8s、`port || 80`，HTTPS 会直接挂。看板的超时要定多少，超时后是整块置灰还是保留上次成功的数据并标「数据可能过期」。
- **轮询与新写入的竞态**：拖拽提交中轮询回来，把卡片刷回旧列怎么办（写入期间冻结该卡 / 写入成功后强制以本地为准重绘）。
- **Jira 拒绝**：workflow 不允许该 transition（403/400），提示里要不要直接给「在 Jira 中打开」的链接。

## 交付

一张「依赖 × 故障 × 界面表现」的矩阵，加写入失败的状态机。

## Answer

**1. 数据源缺失 → 第六态「无法判定」**：阶段徽章变为灰底虚线框，文案「无法判定」；顶栏一条可折叠横幅：「GitLab 未配置 · MAGR3/NEX/IB 的 Jenkins job 未填」。卡片**不会被谎报**成「未提交」。

**2. 写入：乐观 + 待提交标记**：拖下即落目标列，卡片半透明并标「提交中」；成功变实，失败自动弹回原列并显示原因。写入期间该卡**冻结**，不参与轮询重绘。

**3. 凭据失效**：401/403 的提示必须指到具体文件（`~/.scrumbuddy/config.json` 的 `jira.password` / `gitlab.token` / `jenkins.token`），不能只说「请求失败」。

**4. 超时**：列表请求 10s、写请求 20s（拉 transitions + POST 两跳）。超时后**保留上次成功数据并标「数据可能过期 · hh:mm」**，不整块置灰。

**5. Jira 拒绝（400/403）**：展示 Jira 返回的字段级 `errors`（能定位到哪个字段），并给「在 Jira 中打开」链接；不做自动重试。

**6. 轮询竞态**：写入中的卡不参与重绘；写入完成后以本地写入结果为准，直到下一次轮询返回一致状态。
