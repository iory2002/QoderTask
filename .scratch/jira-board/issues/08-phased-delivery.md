# 分阶段落地与验收

Type: grilling
Status: resolved

## Question

这一版的需求（工作区看板 + 跨列写 Jira + 必填表单 + MR 徽章 + Jenkins 构建阶段 + 轮询）一次做完风险太大，尤其写在真实 Jira 上是不可逆的。怎么切，才能每一期都可用、都能验收？

需要定的：

- **切法**：按「只读看板 → 写回 → 构建阶段」切，还是按「Jira 全通 → GitLab 徽章 → Jenkins」切？前者的第二期就开始动真数据，后者可以先把整条链路只读跑通。
- **每期的验收标准**：一句话能验的判据（例如「v0.3：打开看板能看到 sprint 全部 issue，Done 列不为空」）。
- **每期明确不做的事**：避免下一期把上一期的临时妥协固化成契约。
- **回滚**：写能力上线后，如果 transition 映射配错批量改坏了状态，有没有办法补救（操作日志 / 前置快照 / 只允许单张操作）。
- **旧功能下线时点**：侧边栏 TODO 面板与 `.todo-data.json` 在哪一期移除，README 何时改。

## 交付

期数、每期范围、验收判据、明确不做清单。它决定 spec 是否要拆成多份，以及 map 是否需要追加新票。

## Answer

**三期，按风险递增切：只读 → 写回 → 构建。**

### v0.3 只读看板
- 工作区 tab（`createWebviewPanel`）+ 活动栏入口；侧边栏 TODO 面板与 `.todo-data.json` 下线，README 注明不可逆。
- 五列（board 配置）+ 不分行 + 项目过滤（MAGR3/NEX/NEX2/IB）+「只看我的」默认开。
- 卡片：类型/key/标题/优先级/Epic chip/评论数/阶段徽章；`Rank ASC`。
- 阶段只到 MR 层（未提交 / MR 待审 / 已 Approve / 无法判定），GitLab 最小只读通道。
- 详情浮层（只读，无推送按钮）。全程不写 Jira。
- **验收**：打开看板能看到自己的 6 张卡；Done 列不为空；阶段徽章与 GitLab 实际状态一致；GitLab 未配置时显示「无法判定」而非「未提交」。

### v0.4 写回
- 拖拽合法性按逐 issue transitions 判定；表单（四类控件 + 预填 + 硬阻断）；软闸门；乐观更新 + 待提交标记 + 失败弹回；写入期间冻结卡片。
- **验收**：把一张 Bug 从 In Progress 拖到 In Test 成功；把一张 Story 拖到 In Test 被拒并提示只能到 In Code Review；必填缺失时字段级报错能定位控件；写失败后卡片回弹且原因可见。

### v0.5 构建阶段
- Jenkins 时间窗判定 + 「已合入待构建 / 已构建 / Build failed」；详情浮层补 build 号、构建绝对时间、分支。
- **验收**：已合入且目标分支有更晚的 SUCCESS 时显「已构建」并给出构建时间；构建进行中不被误判为失败；job 未配置的项目显示「无法判定」。

### 每期都不做
- 同列排序、手动标记完成、本地卡片、泳道/行分组、回退拖拽、写 Jira 评论、MR 列表与评审操作、插件内编辑其它 Jira 字段。

### 回滚
- 每期都是新 vsix 版本，回退=重装上一个 vsix。
- 写能力上线后仍只允许**单张卡单次写**，没有批量操作，因此误操作面天然受限；Jira 自身的 issue history 是唯一的审计痕迹（不写评论）。
