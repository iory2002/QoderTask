## Question

有了事实库和 GitLab 时间戳，指标才有意义。要定"第一版做几个、每个怎么算、界面标什么":

1. **最小集合**：候选——前置时间（首次提交 → 合入）、评审等待（MR 创建 → 首个 approve）、评审往返次数、构建成功率、构建时长 P50/P90、每日合入数、返工率（退回 In Progress 的卡）。选 3~4 个，其余进 fog。
2. **口径**：前置时间从"首次提交"还是"Jira 进 In Progress"起算？按卡算还是按 MR 算（一张卡多个 MR 怎么办，取首个合入还是最后一个）？跨 sprint 的卡归哪一轮？
3. **数据起点**：库里最早可信的日期怎么标，界面上怎么写（"自 2026-11-10 起"）。
4. **呈现位置**：嵌在现有两个板里（顶栏一行数字）还是单独一个面板；如果嵌，会不会把"看板"变成"报表"而失去焦点。
5. **明确不做的**：不追求跨团队横向比较，不做排名/绩效（避免被当成考核工具，反而没人敢用）。
6. **失效处理**：数据不足（样本 < N）时怎么显示——"样本不足"而不是画一条误导的趋势线。
