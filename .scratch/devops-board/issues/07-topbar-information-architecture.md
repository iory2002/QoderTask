# 07 顶栏信息架构：两板各自的「该我动」，跨板数字放哪

Type: grilling
Status: closed
Blocked by: —

> **2026-11-10 关闭：无独立价值。**
> ① “我拖住的卡”的数字是聚合，每张卡的事实已经由阶段徽章表达（`已合入待构建` / `已构建` 与它所在的列并排一看就知），只是“数一下”不构成新信息；
> ② “待我审”在 GitLab 板是一整列，活动栏角标又是一个，再上顶栏 chip 就是第三次重复；
> ③ 真正不存在的事实只有两个，且不该放顶栏：MR 的 `has_conflicts` / `blocking_discussions_resolved`（标在卡上），以及“合入后多久未推进”（详情浮层一行）。两者已并入 [08](08-copy-exits-and-alerts.md)。

## Question

现在两个板各自有顶栏（同步时间、刷新、只看我的等），活动栏两个图标各有角标，TreeView 里各有两行数字。要定"今天该我动的"落在哪，不新增第三个需要维护的界面：

1. **Jira 板顶栏**：放"我拖住的卡"（MR 已合入但 Jira 没推进 / 卡在 In Code Review 超过 N 天）——口径怎么定、点一下是过滤还是打开列表。
2. **GitLab 板顶栏**：放"待我审 N（最久 3 天）/ 等我改 M"——"等我改"怎么判定（我提交的 MR 有未解决的讨论？被 requested changes？还是只是没 approve）。
3. **跨板数字**：放侧边栏 TreeView 新增一行，还是在两个板各自显示自己那半，不合并。合并需要一个"跨数据源 join 的时刻"，会引入两个 BoardState 的时序耦合。
4. **状态栏**：要不要在编辑器状态栏放一个极简入口（如 `待审 4 · 拖住 1`），点击打开对应板。代价：状态栏位子有限，且可能与其它扩展打架。
5. **空态**：三项全为 0 时显示"清空"还是直接隐藏整行。

## 完成标准

一张信息架构图（哪一行、什么数字、点击去哪、数据来自哪个 BoardState）+ 明确"不做什么"，写进 `research/07-topbar-ia.md`。若选"跨板合并"，必须同时说明数据不一致时怎么显示。
