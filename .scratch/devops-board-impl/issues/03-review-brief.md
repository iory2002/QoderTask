# 03: 评审要点单：复制文案带 diff 事实

**What to build:** 点「用 Qoder 审查此 MR」后，剪贴板里的指令除链接与 diff 路径外，还带一份事实清单：改动文件数与增删行、按目录聚类的改动、敏感变更命中项、关联的 Jira 卡、当前批准情况。只写能证明的事实，不给"建议重点关注"这类主观判断。

**Blocked by:** None (can start immediately)

**Status:** resolved

- [x] 复制文案包含：文件数 + 增删行、目录分布、敏感变更、关联 Jira 卡、批准现状
- [x] 某类事实缺失时整行省略，不写"无"
- [x] 敏感变更为固定规则集合：构建工程文件、依赖清单、构建脚本、扩展与前端共享的类型、SQL 与迁移目录
- [x] diff 拉取失败时退回只带链接的指令并提示（沿用现有行为）
- [x] 文案拼装是纯函数，单测可直接断言输出
- [x] 不新增请求（diff 本来就要拉）

## Comments

- `buildReviewRequest` 改为单一入参对象；事实全部来自已拉下的 `/diffs` 响应（逐文件用 `countChangedLines` 数增删行）与 MR 列表里的审批/ Jira key。
- 敏感规则表固定五项，命中时按规则表顺序输出；未命中不写「敏感变更：无」。
- diff 超过 3 页（300 文件）时写「至少 N 个文件」，不把截断当完整。
- 测试：`test/review-request.test.ts`（含规则表与行数统计）。
