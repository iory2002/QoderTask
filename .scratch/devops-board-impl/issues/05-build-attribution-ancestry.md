# 05: 构建归因改为 SHA 祖先判定

**What to build:** 卡片上的「已构建」只在"最新一次成功构建的代码树包含本次合入"时出现，并且详情写明是哪个构建、什么时候启动。取不到 SHA 时退回时间窗判断，并在界面上明确标注为「推断」。

**Blocked by:** 01（同一批取数代码，先落地翻页与 epoch 解析，避免并行改动打架）

**Status:** ready-for-agent

- [ ] 判定改为祖先关系：合入的 merge commit 是构建 SHA 的祖先（或相等）才算包含
- [ ] 只有 `SUCCESS` 算；`FAILURE` 与进行中的构建都不算「已构建」
- [ ] 卡面不写构建号；详情写「最新成功构建 #N（启动时间）包含本次合入」并附链接
- [ ] 构建无 SHA 或祖先判定失败 → 退回时间窗，并在详情标注「推断」
- [ ] 阶段单测基线更新，新增"同一 SHA 被多次构建""FAILURE 不算"两个用例
- [ ] 文档词汇同步：`已构建` 的含义与"不等于产物里有"这句边界写进术语表
