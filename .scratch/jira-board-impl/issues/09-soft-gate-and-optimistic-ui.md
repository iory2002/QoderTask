## Comments

- 乐观更新落在**确认表单之后**（spec §10 的顺序：弹表单 → 确认 → 乐观移动 + 提交中）。`BoardState.transition()` 先把卡片换到目标状态、`pending` 里记下「原状态 / 目标状态」再 `publish()`，此时 `pendingKeys` 会让卡片带上 `.pending`（半透明 + 「提交中…」）并且不可再拖。
- 轮询不覆盖：`load()` 拿回新卡片后调用 `reapplyPending()`，把写入中的卡片重新钉在目标状态，因此不会出现「新列 → 旧列 → 新列」的抖动。
- 失败弹回：`catch` 里按 `pending` 记下的原状态还原并立即 `publish()`，随后回 `card:transitionResult.ok=false`，表单和 toast 都能拿到原因。
- 软闸门是纯函数 `checkSoftGate()`，7 条单测覆盖：未提交 / 待审 / 已批准 / 无法判定都会拦，`已合入` 放行，构建失败单独提醒，未追踪项目不拦，非 In Test 列不拦。
- 闸门阈值挂在「已合入」而不是「已构建」：构建一天两次、单次 5～20 小时，卡在构建上等于永久阻塞。
- 闸门选「取消」什么都不发；选「仍然推进」只是把表单打开，真正的写入仍走 08 的单卡单次通道。
